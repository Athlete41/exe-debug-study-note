# 驱动协议文档（逆向还原）

## 1. 总览

| 项目 | 内容 |
|---|---|
| 设备对象 | `\Device\Cracker`（FILE_DEVICE_UNKNOWN, 0x22） |
| 符号链接（用户态访问名） | `\\.\Cracker` |
| IOCTL 指令码段 | `0x238000 ~ 0x23804C`（共 14 个） |
| I/O 方式 | **METHOD_BUFFERED**（输入输出共用一块 SystemBuffer） |
| 主要功能 | 进程内存读写 / 模块与函数定位 / 虚拟内存操作 / DLL 注入 / 远程线程 / 进程控制 / 文件操作 / 自我保护 / 自卸载 |

---

## 2. 通用通信协议

### 2.1 打开设备
```c
HANDLE hDev = CreateFileW(L"\\\\.\\Cracker",
                          GENERIC_READ | GENERIC_WRITE,
                          0, NULL, OPEN_EXISTING, 0, NULL);
```
打开成功即完成初始化（驱动会把打开者 PID 记入 `g_ElevatedPid`，用于后续权限回调）。

### 2.2 调用方式
```c
DeviceIoControl(hDev,
                IoControlCode,   // 指令码
                pInBuf,          // 输入缓冲（即 SystemBuffer）
                inSize,          // 输入大小
                pInBuf,          // METHOD_BUFFERED：同一缓冲也承载输出
                outSize,         // 输出缓冲大小（驱动成功时把该值写回 IoStatus.Information）
                &bytesReturned, NULL);
```

### 2.3 SystemBuffer 布局（核心！）
驱动把输入缓冲**伪装成 IRP 结构**读取参数，各字段只是"长得像 IRP"，实际是自定义参数槽。**偏移固定为 40 字节大小**：

```c
typedef struct {
    ULONG_PTR arg0;   // +0x00  对应 IRP.Type（伪装名）
    ULONG_PTR arg1;   // +0x08  对应 IRP.MdlAddress
    ULONG_PTR arg2;   // +0x10  对应 IRP.Flags
    ULONG_PTR arg3;   // +0x18  对应 IRP.AssociatedIrp.MasterIrp
    ULONG_PTR arg4;   // +0x20  对应 IRP.ThreadListEntry.Flink
} IOCTL_PARAMS;       // 总大小 0x28 = 40 字节
```

> 传入的 `outSize` 至少要覆盖需要的输出量；驱动成功时 `IoStatus.Information` = 传入的 `OutputBufferLength`，失败 = 0。

### 2.4 返回约定
- 各处理函数返回值（0 = 成功）会写回 **SystemBuffer + 0x00**（即 arg0 位置）。
- 部分指令的真实结果通过 **arg3 / 对应 pResult 指针** 写回（见各指令说明）。
- 未匹配任何已知指令码 → 驱动返回 `STATUS_UNSUCCESSFUL (0xC0000001)`。

## 3. 指令码明细

> 说明：`pid` 一律为**目标进程 PID**；方向类指令 `arg4==0` 读、非 0 写（已核对 `MmCopyVirtualMemory` 实参顺序）。

### 3.1 `0x238000` — 读写内存（MmCopyVirtualMemory）
```c
arg0 = pid;        // 目标进程
arg1 = TargetAddr; // 目标进程内地址
arg2 = Size;       // 字节数
arg3 = LocalBuf;   // 调用者缓冲（源/目标）
arg4 = Direction;  // 0=读(目标→LocalBuf)  非0=写(LocalBuf→目标)
```
- 校验：pid 非法或地址低于 0x10000 → 返回 2；进程查找失败 → 返回 3。

### 3.2 `0x238004` — 读写内存（MDL 锁页版，隐蔽通道）
参数同 3.1，方向约定相同。实现走 `KeStackAttachProcess + IoAllocateMdl + MmProbeAndLockPages + MmMapLockedPages`，可绕开针对 `MmCopyVirtualMemory` 的检测。
> ⚠️ 该处理函数为 void（混淆后不返回可靠状态），调用方一般只按"发起成功"处理。

### 3.3 `0x238008` — 取模块基址
```c
arg0 = pid;
arg1 = ModuleName;  // ANSI 模块名（如 "kernel32.dll"），驱动内部转 Unicode
arg3 = pResult;     // 输出：模块基址
```
内部：`KeStackAttachProcess` + 遍历 PEB LDR 模块链表（自动兼容 32/64 位）。

### 3.4 `0x23800C` — 取导出函数地址（GetProcAddress）
```c
arg0 = pid;
arg1 = ModuleBase;  // 模块基址（可用 0x238008 取得）
arg2 = FuncName;    // ANSI 函数名（驱动拷入本地 4KB 缓冲）
arg3 = pResult;     // 输出：函数地址
```
- 函数名长度 > 0x1000 → 失败（0xC0000001）。
- 内部：挂到目标进程后解析 PE 导出表（按名查）。

### 3.5 `0x238010` — 远程分配内存（VirtualAllocEx）
```c
arg0 = pid;
arg2 = Size;        // 分配大小
arg3 = pResult;     // 输出：分配的基址
```
内部：`ZwAllocateVirtualMemory`，类型 `MEM_COMMIT|MEM_RESERVE (0x3000)`，保护 `PAGE_EXECUTE_READWRITE (0x40)`。

### 3.6 `0x238014` — 远程释放内存（VirtualFreeEx）
```c
arg0 = pid;
arg1 = BaseAddr;    // 要释放的基址
```
内部：`ZwFreeVirtualMemory`，类型 `MEM_RELEASE (0x8000)`。

### 3.7 `0x238018` — 修改内存保护（VirtualProtectEx）
```c
arg0 = pid;
arg1 = BaseAddr;    // 目标地址
arg2 = Size;        // 字节数
arg3 = pOldProtect; // 输出：旧保护属性
arg4 = NewProtect;  // 新保护属性（如 PAGE_EXECUTE_READWRITE=0x40）
```

### 3.8 `0x23801C` — 按进程名取 PID
```c
arg0 = ProcessName; // ANSI 进程名（如 "HuntGame.exe"）
arg3 = pResult;     // 输出：PID
```
内部：`ZwQuerySystemInformation(SystemProcessInformation)` 枚举 + 按名匹配。

### 3.9 `0x238020` — 设置/清除进程保护标志
```c
arg0 = pid;
arg4 = Flag;        // 0=清除  非0=设置
```
内部：对目标进程 **EPROCESS+0x440** 写入/清零标记，并配合全局缓存。配合 `ObRegisterCallbacks` 的权限过滤使用。

### 3.10 `0x238024` — 终止进程
```c
arg0 = pid;
```
内部：`KeStackAttachProcess + ZwTerminateProcess(0)`。

### 3.11 `0x238040` — 卸载驱动（自毁）
无参数。调用后驱动执行 `DriverUnload`（注销回调）、`IoDeleteSymbolicLink`、`IoDeleteDevice`——**设备消失，驱动不再可用**。

### 3.12 `0x238044` — 删除文件
```c
arg0 = FilePath;    // ANSI 完整路径（如 "C:\\Windows\\System32\\xxx.dll"）
```
内部：`IoCreateFileSpecifyDeviceObjectHint + ObReferenceObjectByHandle` 置删除标志 + `ZwDeleteFile`（可删被占用/锁定文件）。

### 3.13 `0x238048` — 远程创建线程（CreateRemoteThread）
```c
arg0 = pid;
arg1 = StartAddr;   // 线程起始地址（目标进程内）
arg2 = Parameter;   // 传给线程的参数
```
内部：`RtlCreateUserThread` + `ZwWaitForSingleObject`（等待 1 秒）+ 关闭句柄。

### 3.14 `0x23804C` — DLL 注入
```c
arg0 = pid;
arg1 = DllPath;     // ANSI 的 DLL 完整路径
```
内部完整链路：`0x238010` 远程分配 RWX → `0x238004` 写入路径字符串 → 取 `kernel32!LoadLibraryA` → `0x238048` 远程线程执行 → 释放内存。

## 4. 典型使用流程（作弊客户端视角）

```
1.  CreateFile("\\\\.\\Cracker")                    // 打开，成为"特权者"
2.  0x23801C  "HuntGame.exe" → pid                  // 定位目标
3.  0x238020  pid, 非0                              // 标记目标(配合保护)
4.  0x238008  pid, "HuntGame.exe" → base            // 拿模块基址
5.  0x238000  pid, base+offset, n, buf, 0           // 读内存(找AOB/数值)
6.  0x238000  pid, base+offset, n, buf, 1           // 写内存(改数值/代码)
7.  0x238018  pid, addr, len, &old, 0x40            // 改保护后写shellcode
8.  0x23804C  pid, "C:\\hook.dll"                   // 注入功能DLL
9.  0x238040                                        // 用完全部后自毁卸载
```

## 5. 注意事项（重要）

1. **加载**：.sys 是未签名驱动，正常系统无法直接加载，需绕过 DSE（测试签名 / 已过期的泄露证书 / 漏洞加载器）——这正是它被归为 BYOVD 高危组件的原因。
2. **错误码是低 16 位语义**：处理函数返回的 1/2/3/5/8 等是自定义小错误码（无效 PID / 地址 / 分配失败 / 非 PE 等），不是标准 NTSTATUS，客户端需要自行映射。
3. **某些指令无可靠返回值**（0x238004 等被混淆 void 化），设计调用方时不要依赖其返回值判断成败。
4. **该文档仅用于逆向分析/学习**。实际部署使用涉及内核级越权 + DSE 绕过，属高风险行为，请自行评估法律与安全边界。
