# cracker.sys 逆向分析 

> 工具: IDA Pro 9.3

> 驱动：`Cracker.sys` ｜ 设备：`\\.\Cracker` ｜ I/O：`METHOD_BUFFERED` ｜ 指令码段：`0x238000~0x23804C`

## 1. 打开设备

```c
HANDLE h = CreateFileW(L"\\\\.\\Cracker", GENERIC_READ|GENERIC_WRITE, 0, NULL, OPEN_EXISTING, 0, NULL);
```

## 2. 调用协议

### SystemBuffer 布局（40 字节）

| 偏移 | 槽 |
|---|---|
| +0x00 | arg0 |
| +0x08 | arg1 |
| +0x10 | arg2 |
| +0x18 | arg3（**输出指针**） |
| +0x20 | arg4 |

### 调用骨架

```c
DeviceIoControl(h, code, &params, 40, &params, 40, &ret, NULL);
```

### 判错（**实测修正版**）

1. `DeviceIoControl` 返回 FALSE → 驱动异常或无效码。
2. 若返回 TRUE，则：
   - **arg0 的状态码是否可信，取决于具体指令**（见下表）。
   - **arg3 输出槽**通常承载实际结果（如 PID、基址），**必须检查其非零性**。

> ⚠️ **重要**：arg3 必须是有效可写地址，否则驱动写入时可能蓝屏。

## 4. 关键指令实测行为详解

### `0x23801C`（取 PID）
- **实测现象**：`status`（arg0）返回一个随机大整数（如 `0x1ba3e520000`），毫无意义。但 `arg3` 正确填充了 PID。
- **安全用法**：仅检查 `arg3 != 0`，忽略 `arg0`。

```python
# Python 正确示例
def getPidByName(h, name):
    buf = create_string_buffer(name.encode())
    pid = c_ulonglong(0)
    _, _ = deviceIoctl(h, 0x23801C, arg0=addressof(buf), arg3=addressof(pid))
    return pid.value  # 直接返回，非零即为有效
```

### `0x238008`（取模块基址）
- **实测现象**：`status` 可靠，成功时返回 `0`；`arg3` 返回基址，成功时非零。
- **安全用法**：两者结合检查：`status == 0 and base != 0`。

### `0x238000` / `0x238004`（内存读写）
- **实测现象**：`status` 可靠（成功为 0）。`arg3`（返回的 result）为随机值，**与数据无关**。实际数据位于提供的本地缓冲中。
- **安全用法**：检查 `status == 0`，然后从 `buf` 中解析数据。

### `0x238024`（终止进程）
- 实测中 `status` 返回 `0`，未检查 `arg3`。

---

## 5. 错误码约定（实际行为）

- 对于 **0x238000 / 0x238004 / 0x238008 / 0x238024**：`arg0` 返回 `0` 表示成功，非 0 表示失败（具体错误码见旧表，但未完全验证）。
- 对于 **0x23801C**：`arg0` 不可用，忽略之。

## 7. Python 参考（已修正）

```python
def getPidByName(handle, name):
    nb = ctypes.create_string_buffer(name.encode('ascii'))
    result = ctypes.c_ulonglong(0)
    # 忽略 status，只取 result
    deviceIoctl(handle, IOCTL_GET_PID_BY_NAME,
                arg0=ctypes.addressof(nb),
                arg3=ctypes.addressof(result))
    return result.value   # 非零即有效

def getModuleBase(handle, pid, name):
    nb = ctypes.create_string_buffer(name.encode('ascii'))
    result = ctypes.c_ulonglong(0)
    status, _ = deviceIoctl(handle, IOCTL_GET_MODULE_BASE,
                            arg0=pid,
                            arg1=ctypes.addressof(nb),
                            arg3=ctypes.addressof(result))
    return status, result.value   # status == 0 且 result != 0 表示成功
```

## 8. 总结：实测结论

- **status 并非万能**，至少 `0x23801C` 不可信。
- **输出槽 arg3 通常承载真实数据**，优先检查它。
- 读写类指令的 `result` 返回值（arg3）是垃圾，直接忽略。
- 其余指令需逐个实测，不能盲目信任文档。

此文档基于实际测试更新，并标注了未测项。后续使用时请自行验证。
