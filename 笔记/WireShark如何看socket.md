### 🥇 第一步：确认是不是 Socket（五元组）
**目标：确认这是不是两个端点之间的正常通信。**

只看这 5 个值：
> **源IP** → **源端口** ， **目的IP** → **目的端口** (协议：TCP/UDP)

- **你截图里的结论**：`192.168.198.131:60663` ↔ `103.120.88.35:8896`，协议 TCP。
- **判断**：源端口是随机高端口（60663），目的端口是固定服务端口（8896）。**这就是一个标准的客户端→服务端 Socket 通信**，没问题。

---

### 🥈 第二步：看 Flags（标志位）—— 决定动作
**目标：这包是来干嘛的？握手、发数据、再见，还是报错？**

只看 Flags 后面的英文缩写：

| 你看到的标志 | 代表意思 | 你的截图是 `PSH, ACK` |
| :--- | :--- | :--- |
| **SYN** | 我要建立连接（拨号） | |
| **SYN-ACK** | 我同意建立连接（接听） | |
| **ACK** | 我确认收到（好的，知道了） | ✅ 有 ACK |
| **PSH** | **我有数据要立刻交给你（别攒着）** | ✅ **有 PSH（核心动作）** |
| **FIN** | 我要挂断（拜拜） | |
| **RST** | 直接摔电话（异常报错） | |

- **判断**：你的包有 `PSH`，说明 **这是一个“带干货”的数据包**，不是空包，非常重要。

---

### 🥉 第三步：看核心数据（Seq/Ack 和 Len）
**目标：数据送没送到？送了多少？**

- **看 `Len`（长度）**：`Len: 234`。**大于 0**，确认了第二步的判断——果然带了 234 个字节的“货”。如果是 0，那前面有 PSH 就矛盾了（空推），那是异常。
- **看 `Seq` 和 `Ack`**：`Seq: 1`，`Ack: 1`。这说明**收发顺序完全正常**，对方发来的数据都确认了，没有丢包重传。

---

### 🏅 第四步：细看异常细节（分片、校验等）
**目标：路上有没有出岔子？**

- **看分片（Fragmentation）**：去 IP 头部找 **`Flags`** 和 **`Fragment Offset`**。
  - 你的截图：`Flags: 0x2, Don't fragment`（不允许分片），`Fragment Offset: 0`（偏移为0）。
  - **结论**：**没有分片**。整个包 274 字节（小于以太网 1500 的 MTU），完整送达。
- **看 TTL（生存时间）**：`128`。这是 Windows 默认值，没被路由改过，说明包没走太远。
- **看 Checksum（校验和）**：显示 `[unverified]`。这只是 Wireshark 没开验证，忽略就行，99.9% 的情况都是对的。

```text
拿到一个包
    │
    ├─ 第1步（定位） → 看 IP:Port → 确认是哪个 Socket 在聊天
    │
    ├─ 第2步（意图） → 看 Flags → SYN? PSH? FIN? 决定这包是干嘛的
    │
    ├─ 第3步（内容） → 看 Len 和 Seq/Ack → 带了多大货？顺序乱没乱？
    │
    └─ 第4步（体检） → 看分片 (DF/Offset) 和 TTL → 有没有被拆开？走了几跳？
```
