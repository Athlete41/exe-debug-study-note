### 📊 守方招式总表（反作弊/AC）

| 类别 | 招式 | 具体操作 | 难度 | 有效性 | 代价/副作用 | 取舍 |
|:---|:---|:---|:---|:---|:---|:---|
| **加载策略** | Boot Start | 注册表`Start=0`，`Group/Tag`抢前 | ⭐⭐ | 高（建立信任根） | 始终运行，隐私争议 | 最激进，争议最大 |
| | 运行时证明 | Win11 25H2 API + TPM追溯检查 | ⭐⭐⭐ | 极高（硬件级不可篡改） | 需TPM 2.0 + Secure Boot | 后加载也能查之前的驱动 |
| **扫描技术** | 模块列表遍历 | 枚举`PsLoadedModuleList`，验签名 | ⭐⭐ | 标准加载有效 | 开销小 | 对手动映射无效 |
| | 内存池暴力扫描 | 遍历内核内存，扫`MZ`特征 | ⭐⭐⭐⭐ | 手动映射有效 | 性能开销大 | 可能误判系统内存 |
| | 代码完整性校验 | 计算游戏`.text`哈希，定时比对 | ⭐⭐⭐ | 代码注入有效 | 读取整个代码段 | 频繁校验导致卡顿 |
| | 签名黑名单 | 维护已知漏洞驱动哈希/证书列表 | ⭐⭐ | 已知BYOVD有效 | 需持续更新 | 对新变种无效 |
| **实时监控** | 进程/线程/模块回调 | `PsSetCreate...Notify`监控创建事件 | ⭐⭐ | 标准加载有效 | 频繁触发 | 对手动映射无效（不触发LoadImage） |
| | 对象回调 | `ObRegisterCallbacks`拦截句柄操作 | ⭐⭐⭐ | 拦截`OpenProcess` | 每次句柄操作触发 | 对直接CR3读写无效 |
| | EPT虚拟化监控 | Intel VT-x在Ring -1监控内存访问 | ⭐⭐⭐⭐⭐ | 极高（硬件级，外挂无法感知） | 性能损耗巨大，VM-Exit频繁 | 最强监控，代价最高 |


### 🕐 时序速查卡

| 先手方 | 攻方处境 | 守方反制 | 攻方难度 |
|:---|:---|:---|:---|
| **AC先手** | 任何标准加载都被捕获 | 回调监控 + 模块扫描 + EPT | ⭐⭐⭐⭐⭐（必须完全无痕） |
| **外挂先手** | 可污染信任根，可劫持回调 | EPT虚拟化“降维监控” | ⭐⭐⭐（但EPT可逆转） |
| **同时启动** | 取决于`Group/Tag`配置 | 同左，看配置细节 | 不定 |


### 💎 核心法则

1. **没有免费午餐**：隐蔽 ↔ 不稳定，稳定 ↔ 易检测。没有既完全无痕又绝对稳定的方案。
2. **三层嵌套博弈**：时序层（谁先加载）→ 痕迹层（能否隐藏）→ 权限层（Ring -1 vs Ring 0）。
3. **攻防持续进化**：每层对抗都要求双方对Windows内核的理解更深一层。
