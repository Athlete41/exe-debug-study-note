### 📜 汇编语法核心结构（规则一）
**格式**：`指令 目标操作数, 源操作数`
**读法**：**从右往左**（把右边的给左边）。

| 写法 | 含义 | 示例 |
| :--- | :--- | :--- |
| `mov a, b` | 把 b 的值赋给 a | `mov eax, 1` (EAX=1) |
| `lea a, b` | 把 b 的**地址**赋给 a（特殊：不取内容） | `lea rax, [rbp-8]` (RAX=rbp-8的地址) |

```
mov eax, [ebx+0x80]   ; 【访问内存】算出地址ebx+0x80，去这个内存地址读取4字节数据存入eax
lea eax, [ebx+0x80]   ; 【只做算术】计算 ebx + 0x80，把求和结果直接放进eax，根本不去内存
```

**场景 1：正统用途：获取变量 / 结构体成员的地址**
```

lea edx, [ebx+4]; 等价C：edx = &(ebx->member_4); edx 得到结构体偏移0x4成员的地址
```
**场景 2：编译器 “偷懒技巧”：用 lea 做快速四则运算**
```
CPU 的lea可以一次完成 基址 + 寄存器*比例 + 常数
支持格式：[reg1 + reg2*1/2/4/8 + 立即数]
所以编译器经常拿它代替 mul/add 组合，运算更快。
```

### 🧩 操作数类型（规则二：看有没有 `[]`）

| 类型 | 格式 | 含义 | 示例（假设 RAX=0x100） |
| :--- | :--- | :--- | :--- |
| **立即数（数值）** | 不带括号的数字 | 直接使用这个数字本身 | `mov eax, 0x10` → EAX=16 |
| **寄存器** | `rax`, `rbx` 等 | 使用寄存器里的值 | `mov eax, ebx` → 把EBX的值给EAX |
| **内存（有括号）** | `[地址]` | 把括号里的数当成**地址**，去这个地址取数据 | `mov eax, [0x100]` → 去内存地址0x100处取4字节给EAX |

### 📐 内存寻址公式（规则三：`[]` 里的数学）

格式：`[ 基址寄存器 + (变址寄存器 × 比例因子) + 偏移量 ]`

| 常见写法 | 翻译（口语） |
| :--- | :--- |
| `[rbp-0x60]` | **栈上**，rbp 地址往下减 0x60 的位置。 |
| `[rax+rcx*8]` | rax 的值 + (rcx 的值 × 8) 算出地址，去那里取数据（常用于数组）。 |
| `[rip+0x1234]` | **当前指令的地址** + 0x1234（64位程序取全局变量常用）。 |
| `[rbx]` | 去 rbx 里存的地址取数据。 |

### 📏 数据大小标识（规则四：看 `PTR`）

因为寄存器有大小，操作内存时必须指明长度。

| 前缀 | 字节数 | 对应 C 语言类型 | 示例 |
| :--- | :--- | :--- | :--- |
| `byte ptr` | 1 字节 | `char` / `uint8_t` | `mov byte ptr [rax], 1` |
| `word ptr` | 2 字节 | `short` / `uint16_t` | `mov word ptr [rax], 1` |
| `dword ptr` | 4 字节 | `int` / `uint32_t` | `mov dword ptr [rax], 1` |
| `qword ptr` | **8 字节** (x64最常见) | `long long` / 指针 | `mov qword ptr [rax], 1` |

> **注**：操作寄存器时不用写 `ptr`（比如 `mov eax, 1` 自然就是 4 字节），只有 `[内存地址]` 时才必须写。

### 🎯 段寄存器前缀（完整版）

格式：`段名:[地址]`。在 Windows x64 中，**99% 的情况下无视 `ss:`/`ds:`/`es:` 前缀**，只看后面的地址即可。

| 写法 | 忽略后 | 备注 |
| :--- | :--- | :--- |
| `qword ptr ss:[rbp-60]` | `qword ptr [rbp-60]` | `ss:` 是栈段，但 x64 下基址为 0，无视 |
| `qword ptr ds:[rax+0x10]` | `qword ptr [rax+0x10]` | `ds:` 是数据段，x64 下基址同样为 0，无视 |
| `mov rax, fs:[0x28]` | **不能无视！** | **32 位程序**：`fs:[0x28]` 是栈保护 Cookie（Security Cookie），用于检测栈溢出，常见于 VS 编译的 Debug/Release 版本。 |
| `mov rax, gs:[0x30]` | **不能无视！** | **64 位程序**：`gs:[0x30]` 指向 **TEB（线程环境块）**，再偏移 `0x60` 可访问 PEB，常用于**反调试**（检测 `BeingDebugged` 标志）。 |

---

### 📌 一句话总结

| 前缀 | 在 x64 下是否重要 | 何时需要关注 |
| :--- | :--- | :--- |
| `ss:` / `ds:` / `es:` | ❌ 无视 | 从不（基址固定为 0） |
| `fs:` | ✅ 仅 32 位程序 | 访问 TEB、PEB、栈 Cookie（`[0x28]`） |
| `gs:` | ✅ 仅 64 位程序 | 访问 TEB（`[0x30]`）、PEB、反调试检测 |

### 🔍 关键指令“一眼识别表”（不用背，看后缀）

| 指令 | 作用（口语化） | 紧跟着看什么？ |
| :--- | :--- | :--- |
| `cmp a, b` | 比较 a 和 b（相当于 a - b，不改值） | 看后面的 `je`/`jne` |
| `test a, a` | 判断 a 是否为 0（相当于 a & a） | 看后面的 `jz`/`jnz` |
| `call x` | 去执行子函数 x | 跳转前看参数（RCX/RDX/R8/R9） |
| `ret` | 返回调用者 | 函数结束 |
| `jmp x` | 无条件跳到 x | 直接跳走 |
| `je` / `jz` | 相等/为0时跳 | **ZF=1 时跳** |
| `jne` / `jnz` | 不等/非0时跳 | **ZF=0 时跳** |
| `jb` / `jc` | **无符号小于**则跳转 / **进位**则跳转 | **CF=1 时跳**（常用于 `cmp a,b` 后判断 `a < b`） |
| `jae` / `jnb` | **无符号大于等于**则跳转 / **不小于**则跳转 | **CF=0 时跳**（跟 `jb` 刚好相反，判断 `a >= b`） |

### 📝 符号与标点符号速查

| 符号 | 含义 | 示例 |
| :--- | :--- | :--- |
| `,` (逗号) | 分隔目标操作数和源操作数 | `mov rax, rbx` |
| `[]` (方括号) | 取地址里的值（内存访问） | `[rbp-8]` |
| `;` (分号) | 注释，跟在指令后面 | `mov eax, 1 ; 这是注释` |
| `$` (美元符) | 代表当前指令的地址（很少见） | `jmp $` (死循环) |
| `+` / `-` | 地址偏移计算 | `[rbp+0x10]`, `[rbx-4]` |

### 🧪 实战对照示例（一秒翻译）

| 你在 x64dbg 看到的 | 直接翻译成中文 |
| :--- | :--- |
| `lea rdx, [rbp-0x60]` | RDX = **栈上** rbp-0x60 这个位置的**地址**。 |
| `mov rax, [rdx]` | 去 RDX 指向的内存地址，取出 8 字节给 RAX。 |
| `cmp eax, 0` | 比较 EAX 和 0（看 EAX 是不是 0）。 |
| `je 0x401005` | 如果上面相等（ZF=1），跳转到地址 0x401005。 |
| `call qword ptr [0x402000]` | 去内存 0x402000 里存着的那个地址，调用那里的函数。 |
