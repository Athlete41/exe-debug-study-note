# 笔记：特征码（Signature）——逆向者的“概率性锚点”

## 1. 它是什么？（物理形式）
特征码就是一段**十六进制字节序列 + 通配符（??）**。
- 例：`48 8B 05 ?? ?? ?? ?? C3`
- **本质**：你给内存里的某段“地形”拍了一张带“马赛克（通配符）”的照片。

## 2. 它是干嘛的？（核心作用）
就两个字：**定位**。
- 你要找“叶子”（血量数据、函数地址），但叶子会飘。
- 你去找“树”（特征码），树是固定的锚点。**搜到树，顺藤摸瓜拿下叶子**。

## 3. 它的生命周期？（逆向者的“猜谜游戏”）
对于逆向者来说，特征码的寿命**永远是个概率问题**，只能凭经验猜。失效来源于两种变化：

| 特征类型 | 逆向者的经验判断 | 生命周期（失效原因） |
| :--- | :--- | :--- |
| **字符串/数据特征**（搜 `"User Name"`） | **脆弱**。这只是“树叶”。 | 加密、国际化、产品经理改文案，**下个版本立刻暴毙**。 |
| **指令/代码特征**（搜 `E8 ?? ?? ?? ??` 或 `FF 15`） | **坚韧**。这是“骨骼/前摇”。 | 只要核心逻辑（如调用API）不变，即使重编译、开ASLR，**这串操作码骨架依然坚挺**。 |

**为什么指令特征生命周期更长？**
因为你提取的是**“动作的前摇”**（比如调用函数前必然有寻址和压栈操作）。这个“前摇”是CPU硬件和编译器惯性决定的，程序员很难推翻它，改字符串却易如反掌。

**一句话收工：**
逆向者提取特征码，就是在**赌“这段字节的稳定性能扛过下一次软件更新”**。押字符串，赌的是产品经理不改词；押指令骨骼，赌的是Intel不改指令集。聪明人都押后者。🎯
